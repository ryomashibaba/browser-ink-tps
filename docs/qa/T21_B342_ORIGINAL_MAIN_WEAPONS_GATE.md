## 原作準拠と断言できない点

- シューター：人間の連射処理とインク弾は存在するが、既存の基本2シューター設定は拡散角0。移動・ジャンプ・着弾ばらつき、塗装密度、当たり判定、被弾反応の真正比較がない。
- ローラー：既存のヨコ振り、空中タテ振り、塗り進みを確認。振り方・範囲・インク量・攻撃/塗り形状の原作に対する独立検証なし。
- チャージャー：チャージ・リリース・レイ攻撃はあるが、フル/途中チャージ・射程・貫通・塗装線・発射時の視認性が未認証。
- 汎用射撃経路：`fireProjectiles` は空き弾スロット取得前にインク消費している。弾数上限時のインク消失の可能性があり、原作再現の前に負の実機検査が必要。現工程では変更しない。
- CPUはメイン11クラスを宣言しているがSOURCE塗装候補の対象は6クラス。宣言済みというだけで7CPUの全武器が原作品質とは言えない。
- モデル、反動、射撃エフェクト、着弾音、UIは映像比較なしではART合格不可。B340真正スクリーンショットも暗く平板な地形と模式的なキャラが支配しておりART REJECT/HOLD。

## 武器完成工程（B341の独立判定後）

まず基本的な**シューター1種を完全な縦切り**で制作する。最初の対象は既存`pulse-sprayer`。
1. W1：公式の定性的な動作とプロジェクト独自の計測値を切り離し、比較の同一条件・射程・時間・画像基準を固定。
2. W2：人間のボタン押下/保持/離し/移動/ジャンプ/弾切れ/弾プール満杯を真正ブラウザで計測。消費→実射撃→塗装を結び付ける。
3. W3：本物のRapier原作25ソリッド、実着弾、原作17塗装面、攻撃対象の実HP/命中・貫通なしを個別試験。
4. W4：実際の3Dモデル、構え、反動、弾の軌道、塗り痕、敵視認性、音を同一5視点・同一入力で比較。
5. W5：人間/CPUの真正射撃経路を分けたまま整合性を確認し、180秒でも射撃品質とフレーム負荷を維持。
6. W6：否定テスト、Windows/Ubuntu CI、真正Chromium、実機品質、ART審査をすべて通過した場合のみ武器単体を合格。

続けてローラー（地上/空中/連続塗り）、チャージャー（チャージ/レイ/塗り線）を**別ゲート**で完成させる。残りの8系統やサブ/スペシャルはそのあと。ユーザーの「完璧」は到達目標であり、確かめていない段階で「原作100%」とすることは禁止。
