# B494 — 同じ真正Chromiumから取得したA1・B2・B4を単一の物理世界で連続再演

固定根拠：Actions #43140584988のB454 B2/B4とB484 A1の60Hz RAW（tick 1153〜1824、672フレーム、671区間）。各CPUの初期位置だけを実測足から設定し、その後は実測された毎tickの移動**変位**を入力し、同一Rapier世界内でKCC決定分を順次積み上げる。B493のように毎フレーム実測足へ戻さない。原作25 solids、CPU半径0.29m／半高0.39m、共通KCC。

計測：実記録と連続再演の乖離、原作床支持、CPU動的接触、B2/B4の最小距離、衝突で移動が制限された区間。結果が失敗・乖離する場合は誤差をそのまま記録し、成功扱いにしない。

限界：実ゲームの7CPU＋人間を再起動したものではなく、観測データを駆動入力とした**隔離された3CPUの継続物理再演**。元のChrome世界と診断世界は別物。足変位を与えているため、自然なAIによる経路選択を証明しない。未収録の4CPUと人間を捏造しない。原作Ver7.2.0の衝突フラグ、中央の自然経路16組、正式4v4、勝敗、ARTは未認証。NavLink・Stage・本体CPU処理・得点は変更しない。

実行：コミットメッセージ `[p0-radar-build-only] [b494-continuous-shared]` で既存のRAWだけをGitHub Actionsから取得し、Vitestを実行する。真正Chromiumや180秒テストは走らせない。結果は `b494-original-three-cpu-continuous-report` に保存。

## 検証の検出感度（陽性対照）
B494本編の連続再演ではKCCの静的・動的衝突イベントが0件だったため、その事実だけで衝突実装の有効性を宣言しない。隔離された元と同じ25 solids・本物のCPUサイズ・共通KCCで、着地点へ0.30mの下向き移動を要求して原作床との衝突を検出する。さらに真正RAWでB2/B4の最短間隔0.611mを観測したtick1724の座標に別カプセルを置き、互いに近づく0.14mの*意図的なQA移動*で、実CPUサイズの動的接触を検出できるか確かめる。
これはゲーム中の自然移動でも成功経路でもない。必要な陽性対照が失敗すれば判定をHOLDして原因を追う。結果は本来のB494 JSONへ `sensitivityPositiveControls` として追記する。
